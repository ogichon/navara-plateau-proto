# BRIEF-CAPTURE — WebGL 自動キャプチャの実現性検証

worktree `exp/capture-loop` で作業。コミットを試み、失敗したら最終報告に明記。デプロイはしない。既存ページの見た目は変更しない。

## 目的

このプロジェクト最大のボトルネックは「描画の目視確認がユーザーの実 Chrome 待ち」なこと。方針再定義（AGENTS.md、2026-11-09）により、許可された実行環境（この VM）で静止画を自動取得し、Muse 自身がビジュアル評価できる制作ループの整備が最優先の基盤課題になった。本ブリーフはその実現性検証。

## 検証タスク

1. **環境棚卸し**: この VM で使えるヘッドレスブラウザ手段を確認する（既存の chromium / chrome バイナリ、Playwright、Puppeteer の有無）。無い場合は `npx playwright install chromium` 等の導入可否・所要時間・容量を実測する（導入できなければ、その事実と理由を報告して止める）。
2. **キャプチャ試作**: `tools/capture/` に最小スクリプトを作る。対象はローカル配信した現行ビルド（`npx vite build` の dist を静的サーバで配信し、対象は awakening.html）。ヘッドレス Chromium で WebGL（SwiftShader 系フラグ）を有効化し、タイルと描画が落ち着くまで待ってから PNG を保存する。待機は固定秒＋描画安定のヒューリスティクス（例: 連続スクリーンショットの差分）で工夫してよい。
3. **成立判定**: 保存された PNG に建物・写真・空が実際に描かれているかを、画像の基本統計（ファイルサイズ、色数/分散、領域ごとの平均輝度など）で裏付ける。真っ黒・真っ白・タイル未着でないこと。所要時間（ページ読込→キャプチャ成立まで）も測る。
4. **限界の明記**: SwiftShader の描画差異（本番 GPU との色・性能の違い）、タイル取得のネットワーク依存、動画キャプチャへの拡張可否を、実測に基づいて書く。「Muse が構図・明暗・色調を評価できる水準か」を判定する（ピクセル単位の品質判定までは要求しない）。

## 出力

- `tools/capture/` のスクリプトと使い方（README か冒頭コメント）。
- 検証結果を `docs/experiments/capture-loop-feasibility.md` に記録（環境、実測時間、成立可否、証拠の数値、限界、推奨する運用形）。
- サンプル PNG は `tools/capture/samples/` に残す（容量が大きい場合は代表1〜2枚）。
- 既存テスト全通過を維持する（本変更は追加のみ）。
